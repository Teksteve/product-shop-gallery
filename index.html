The Product Shop

A reusable system for running every client and product to one high standard. A small team of agents does the work, reading from a shared shelf of knowledge and reaching for a procedure when a task repeats. Below is how it works, and what it is building.

The loading model · depth without bloat

Anything loaded every session competes for a limited instruction budget. Load every philosophy into every conversation and the agents follow every standard worse. The fix is progressive disclosure: keep the always-on layer lean, and load depth only when that kind of work is actually happening.

Always onLean core
Loaded every session. Only what is universally true and short.
firm identity + hard rules
Who the shop is and the non-negotiables: never em dashes, benefit-first, honest over impressive, show drafts first.
project map (per client)
What this product is, its stack, current state, and key gotchas. The lean context file.
Editing test for every line: would removing this cause a mistake? If not, cut it.

The quality floor · unmistakably human

Every producing agent runs one check before calling anything done: would this be mistaken for AI-generated, and where exactly? The root cause is the absence of intention, the statistical average of everything made confidently, with no specific human choice behind it. The fix, in a word, is to humanize it.

Images
Over-glossy plastic look, hyper-symmetry, mangled hands and text, the generic gradient palette, subjects floating with no context.
Video
Morphing textures, slightly wrong physics, dead eyes, uncanny smoothness, cuts that break continuity because no real space existed.
Copy
Em dashes, the "not just X, it's Y" cadence, relentless three-part lists, puffery, confident blandness with nothing at stake.
Apps / UI
The default gradient hero, three feature cards, emoji bullets, spacing that is technically fine but has no point of view.
The antidote is intention. Specificity over generality, a real point of view, deliberate imperfection and human texture, restraint, and references to actual craft rather than the average of everything. Work saturated with specific human choices cannot be mistaken for machine-made.
Where the work lives · three workspaces
Chat
Think · decide · review
Fast, decision-heavy work. Design dialogue, architecture calls, copy critique. Where agents advise and you steer each move.
Claude Code
Build · in the repo
Anything touching the codebase. Standards live in the repo, so engineering rigor gets checked against real code.
Cowork
Delegate · execute
Multi-step execution once the thinking is done: running an agent across a whole screen set or a full deck.

The rule: chat is where you decide, Cowork is where you delegate the doing, and Code is where anything touching the codebase happens.

Operating habits · what keeps it from rotting
Keep the always-on layer lean
Everything loaded every session competes for a limited budget. Depth goes in on-demand skills, not the core.
Record decisions in the same session
When a real decision lands, it goes into the project's decisions.md that session, with its reasoning. A stale file is worse than a missing one; it confidently misleads.
Gotchas grow from real mistakes
When something goes wrong, the correction goes into the file so it never repeats. A living feedback loop, not a guessed-at manual.
Agents are honest, not flattering
Every role is instructed to tell you when something is not good enough. An agent that only validates cannot make work world-class.
Principles universal, voice per client
Craft standards live at the firm level; specific expression lives per client. This is what stops every client's work looking the same.
Do not over-build
Simple beats complex. One lens at a time, not six personas at once. Context discipline over architectural cleverness.
